# 事件系统

> 状态：数据结构已定义，3 个示例事件，UI 与结算未接入。
> 代码：`map/content/map_event_data.gd`、`map/content/map_event_choice.gd`、`map/res/data/events/`
> 相关：`docs/地图系统.md`、`docs/商店系统.md`、`docs/资源需求.md`

未知事件节点随机触发一个事件，玩家从若干选项中选择，按选项结算。事件是商店之外的另一条调卡途径。

## 设计草案

以下来自提案，文案全部待写。

| 事件 | 效果 | 当前支持 |
| --- | --- | --- |
| 自选删牌 | 随机若干张让玩家删 1 张，也可以不删 | 否 |
| 增强牌 | 随机若干张让玩家增强 1 张 | 否 |
| 意外伤害 | 扣血 | 是（`health_delta`） |
| 意外加牌 | 从特定牌库加一张，有好有坏 | 否 |
| 自选加牌 | 随机若干张选 1 张，可以跳过 | 否 |
| 血量换金币 | 选择是否冒受伤风险换金币 | 是（`health_delta` + `gold_delta`） |

六类事件里有四类要动卡组，这是当前实现的主要缺口。

## 当前实现

| 类 | 字段 |
| --- | --- |
| `MapEventData` | `id`、`title`、`body`、`choices: Array[MapEventChoice]` |
| `MapEventChoice` | `label`、`result_text`、`gold_delta`、`health_delta`、`max_health_delta`，以及 `apply(player)` |

`MapContentPool.events` 指向 `map/res/data/events/` 下的三个示例事件，只覆盖金币、生命、生命上限三种结算，用于验证数据流。选项的 `apply()` 目前没有调用方。

## 与提案的差距

- 结算只支持数值增减，无法改卡组。需要给 `MapEventChoice` 加卡组字段（删 N 张、加 N 张、增强 N 张），或改成可插拔的结算资源。
- 没有"随机若干张让玩家选"的流程，需要事件专用的选牌界面。
- 没有选项条件（金币不足、生命不足时置灰或隐藏）。
- 没有事件池权重与重复控制。
