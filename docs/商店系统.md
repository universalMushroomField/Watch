# 商店系统

> 状态：数据结构已定义，UI 与结算未接入。
> 代码：`map/content/shop_entry.gd`、`map/content/shop_stock_data.gd`、`map/res/data/shop_stock.tres`
> 相关：`docs/地图系统.md`、`docs/事件系统.md`、`docs/资源需求.md`

商店是局内两条调卡途径之一（另一条是事件），用金币换取卡牌、删牌、增强和道具。

## 设计草案

以下来自提案，价格与次数全部待定。

### 服务

| 服务 | 说明 | 价格 | 次数 |
| --- | --- | --- | --- |
| 买牌 | 从系统牌库抽 n 张展示在商店面板 | 因牌而异 | — |
| 删牌 | 移除卡组中的一张 | 待定 | 每次商店 x 次 |
| 增强卡牌 | 优化卡牌的数值 | 待定 | 每次商店 y 次 |
| 道具（含治疗） | 消耗品，如治疗物品 | 待定 | — |

### 金币来源

- 战斗奖励。
- 在更少回合内击败怪物可以额外奖励。

金币目前没有产出：战斗不结算奖励，地图节点也不发放金币。商店要能玩，得先补上这条链路。

### 商人台词

分类：遇见 / 玩家低血量 / 打开面板 / 买下一件 / 打开面板但什么都不买 / 买了之后离开。每类多条随机。台词文本全部待写，见 `docs/资源需求.md` W-04。

## 当前实现

| 类 | 字段 | 说明 |
| --- | --- | --- |
| `ShopEntry` | `card`、`price`、`stock` | 单件商品，默认 50 金币、1 件库存 |
| `ShopStockData` | `entries`、`heal_price`、`heal_amount` | 整间商店，默认治疗 30 金币回 20 |
| `MapPlayerState` | `gold`、`spend_gold()` | 扣款已实现 |

`MapContentPool.shop_stock` 指向 `map/res/data/shop_stock.tres`（两张牌，45 / 55 金币，各 1 件）。但 `MapContentPool` 目前没有被任何脚本读取，商店节点的内容是占位 `Label`。

## 与提案的差距

| 提案服务 | 现状 |
| --- | --- |
| 买牌 | 数据结构支持 |
| 治疗 | 有价格与数量字段 |
| 删牌 | 无。卡组是 `Array[CardData]`，需要按索引或实例删除 |
| 增强 | 无。`CardData` 是共享资源，增强必须先有"卡牌实例" |
| 道具 | 无 |
| 金币来源 | 无 |

增强是最麻烦的一项：现在卡组里存的是 `CardData` 资源引用，改一张会改掉所有同名牌。要么引入卡牌实例（`CardInstance` 包一层数值），要么在增强时复制资源。
