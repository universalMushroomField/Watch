# 资源需求

> 细节大多还在讨论中，这里只记方向，不追求条目化。想到什么往对应分节里加一条即可。
> 括号里的 P0 / P1 / P2 只表示先后：**P0** 不解决就没法继续 / **P1** 影响体验 / **P2** 打磨。

## 文案

- **序列符号定名**（P0）：提案写"红/蓝"，代码是 `ATTACK/DEFENSE`，卡面写"攻/守"，三套并存；"易/白/灰"的含义也还没定。所有卡牌文案和序列 UI 都卡在这一步。
- **货币名与界面文案**（P1）：货币当前叫「活性晶珀」，可能还会改；全部界面文案与货币名集中在 `ui/text/game_text.tres`，改名只改这个文件，不用动脚本和场景。
- **卡牌名称与描述**（P0）：基础的攻、守，以及现有 7 张原型牌。文案风格（动词式还是名词式、字数上限）也一起定。
- **商人台词**（P1）：遇见、玩家低血量、打开面板、买下一件、打开但不买、买后离开，每类几条随机。
- **事件文案**（P1）：标题、正文、选项、结果提示。六类事件都还空着。
- **敌人文案**（P1）：小怪与 Boss 的名号、图鉴描述、意图文案。
- **极端度阶段文案**（P2）：六个阶段的生物方/人类方文案已有草稿，需要润色统一语气。
- **界面标签**（P2）：崩解度、甲、序列、牌堆、回合等，统一用词。
- **收集品名称与描述**（P2）。

## 美术

- **序列条 UI**（P0）：色块、长度上限、剩余计数。现在的序列是文字按钮，玩家读不出资源状态；提案里的配图可以直接当参考。
- **卡面模板与插画**（P1）：模板一套，原型卡各一张。
- **小怪与 Boss 立绘**（P1）：三种小怪，三个 Boss 的立绘和战斗背景。
- **商人立绘与商店面板**（P1）。
- **事件插图**（P2）。
- **货币图标**（P1）：`ui/art/currency_icon.png` 现在是 32×32 的占位像素晶珀，顶栏按 24 px 最近邻显示；替换同名文件即可，代码会自动换图。
- **收集品图标**（P2）。
- **地图节点图标**（P2）：现在是单字 `Label3D`。
- **崩解度上升与战斗胜负的屏幕效果**（P2）。

## 数值

- **卡牌数值与费用曲线**（P0）：序列消耗、伤害、格挡、抽牌。
- **敌人血量与行为表**（P1）：以及遭遇编组。
- **崩解度减益曲线**（P1）：每阶段给什么减益、加成系数多少。
- **商店经济**（P1）：价格、删牌/增强次数、治疗价格。
- **事件概率**（P2）：事件池权重与触发概率。
- **收集品强度**（P2）：池子大小与单件强度。
- **局外评价与解锁成本**（P2）。

## 当前阻塞项

按"没有它就没法继续"排序：

1. 序列符号定名——卡牌文案、序列 UI、教程都等它。
2. 卡牌名称、描述与数值——战斗能跑，但没法测平衡、没法做卡池。
3. 序列条 UI——机制本身还没被玩家看见。
4. 金币产出——战斗不结算奖励，商店和事件的经济全部空转（见 `docs/商店系统.md`）。
