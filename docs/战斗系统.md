# 战斗系统

> 状态：核心规则已实现，`fight/templates/base_fight.tscn` 可单独运行；尚未接入地图。
> 代码：`cards/scripts/`、`effect/`、`fight/script/`、`character/scripts/`
> 相关：`docs/敌人与Boss.md`、`docs/资源需求.md`

本作没有费用。出牌的代价是**序列**：一套有上限的攻/守符号栈。牌打出时消耗序列中的一段，并在原位置生成新符号——出牌顺序本身就是资源规划。

## 术语对照

## 序列规则

实现于 `cards/scripts/card_sequence.gd`。

- 下标 0 是序列顶，最新压入的符号在最前；尾部是最早的符号。
- `push()` 压入顶部，超过 `max_length` 时从尾部裁掉，保留最新的部分。
- `insert_symbols(start, symbols)` 在原位置插入符号，不移动已有符号的相对顺序。
- `consume(pattern, start)` 消耗一段连续子序列；`YI` 可匹配 `ATTACK` 或 `DEFENSE`。
- `max_length` 来自 `CardDeck.sequence_limit`，当前 `deck.tres` 设为 6，由 `CardManager.get_deck()` 接到 `CardSequence` 上。

出牌结算顺序（`cards/scripts/card_manager.gd` 的 `play()`）：

1. 校验落点位置与所有 `Effect.can_apply()`。
2. `sequence.consume(cost, start)` 消耗费用。
3. `sequence.insert_symbols(start, replacement)` 在原位置插入替换符号。
4. 若 `kind` 是 `ATTACK` / `DEFENSE`，`push()` 一个新符号到顶部。
5. 提交效果：立即效果当场执行，阶段效果排队。
6. `extra_draw` 抽牌。
7. 进弃牌堆，或按 `exhaust_on_play` 进除外堆。

可落点位置由 `get_play_positions()` 给出：

| 情况 | 允许的位置 |
| --- | --- |
| `cost_at_top = true` | 仅序列顶（0） |
| `sequence_cost` 为空 | 仅 0（等价于空操作） |
| 其他 | 所有匹配起点 |

消耗和压入是两步独立动作。例如"消耗 1 红、压入 3 红"会先删掉一个红，再在顶部压入三个红。

## 卡牌数据

实现于 `cards/scripts/card_data.gd`。

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `id` | `StringName` | 唯一标识 |
| `display_name` / `description` | `String` | 卡面文案 |
| `kind` | `Kind` | `ATTACK` / `DEFENSE` / `SPECIAL`，决定是否自动压入符号 |
| `sequence_cost` | `Array[Symbol]` | 消耗的连续子序列 |
| `cost_at_top` | `bool` | 是否只能在序列顶结算 |
| `sequence_replacement` | `Array[Symbol]` | 消耗位置插入的新符号 |
| `extra_draw` | `int` | 结算后额外抽牌 |
| `exhaust_on_play` | `bool` | 打出后除外 |
| `effects` | `Array[Effect]` | 效果列表 |

`kind` 只影响自动压入；特殊牌靠 `sequence_replacement` 手动改写序列。现有原型卡（`cards/templates/character_a/card_tres/`，共 9 个资源，含基础的攻、守）只用于验证机制，数值与文案未定稿，不作为设计定稿——定稿见 `docs/资源需求.md` 的文案需求。

提案列出的序列操作类型与当前字段的对应关系：

| 提案操作 | 当前支持方式 |
| --- | --- |
| 顶部压入 | `kind` 自动压入，或 `sequence_replacement` |
| 顶部消耗 | `sequence_cost` + `cost_at_top` |
| 颜色更替 | `sequence_replacement`（原位置插入不同符号） |
| 全局模式匹配后消耗/替换 | `sequence_cost` + `sequence_replacement`，不限位置 |
| 翻转整个序列 | **无支持**，需要一个改写序列的效果类 |

## 卡组

实现于 `cards/scripts/card_deck.gd`。

| 字段 | 作用 |
| --- | --- |
| `turn_draw_count` | 每回合抽牌数 |
| `sequence_limit` | 序列长度上限，`-1` 不限 |
| `sequence_carryover` | 回合结束时保留的序列尾部符号数 |
| `cards` | 初始牌组 |
| `reward_pool` | 战斗奖励候选 |

`cards/templates/character_a/deck.tres` 当前是 8 张起手（抽牌数 8）、序列上限 6、保留 2 个符号、16 张牌、7 张奖励池。这三项数值只写在卡组资源里，`CharacterSelectable` 不再单独导出；`RunPlayerState` 开局复制一份卡组，局内加牌走 `add_card()`。

## 牌堆

四堆：抽牌堆、手牌、弃牌堆、除外堆。

- 开局全部进抽牌堆并洗牌。
- 抽牌堆空时把弃牌堆整体洗回再抽。
- 除外堆本场不回收。
- 回合开始抽 `turn_draw_count` 张。
- 回合结束手牌**全部**进弃牌堆。

与提案的差异：

| 规则 | 提案 | 当前实现 |
| --- | --- | --- |
| 手牌 | 每回合补充到 5 张，保留上回合剩余手牌 | 每回合抽固定张数，回合结束全弃 |
| 开局保底 | 必有一张 0 费牌上手 | 无 |
| 序列上限 | 有上限，满了丢弃最前端 | 上限 6，超限时从尾部裁 |
| 格挡 | 只持续一回合 | 永久保留 |

## 格挡与伤害

实现于 `character/scripts/character.gd`。

- `armor` 是护甲值，界面显示"甲"。
- `prepare_damage(amount, source)` 先查指定来源的伤害抵消（命中即消耗），再由护甲吸收，返回剩余伤害。
- `apply_resolved_damage()` 扣血，归零时发 `died` 信号。
- 指定来源的抵消在 `CardManager.start_turn()` 里清空；`armor` 目前没有任何清除逻辑，会一直累积。
- 待办：按提案改成回合结束清空护甲。

## 效果系统

实现于 `effect/` 与 `fight/script/effect_processor.gd`。

- `Effect` 基类：`immediate`、`effective_stage`、`prepare(sequence, context) -> Callable`、`requires_target()`、`can_apply(context)`。
- `EffectProcessor` 在提交时复制效果并取回结算函数；立即效果当场执行，阶段效果按 `effective_stage` 排队，`enter_stage()` 时按提交顺序结算同阶段项。
- 阶段枚举：`BattlePhase.Stage { START, DRAW, PLAYER, END, ENEMYTURN, FINISHED }`。
- 现有效果：`DamageEffect`（单体/全体）、`ArmorEffect`、`DrawCardsEffect`、`BlockNextDamageEffect`。
- context 约定键：`player`、`target`、`enemies`、`card_manager`。

## 回合流程

| 阶段 | 内容 |
| --- | --- |
| `START` | 战斗开场，结算开场效果 |
| `DRAW` | 抽牌 |
| `PLAYER` | 玩家出牌、弃牌，可结束回合 |
| `END` | 手牌进弃牌堆，序列保留尾部 `sequence_carryover` 个符号 |
| `ENEMYTURN` | 敌人按数组顺序各行动一次 |
| `FINISHED` | 一方全灭，停止结算 |

`fight/script/base_fight.gd` 的 `end_player_turn()` 是主要链路：切到 `END` → 判胜负 → `card_manager.end_turn()` → 切到 `ENEMYTURN` → 逐个 `enemy.take_turn()` → `_begin_player_turn()`（`DRAW` → 回合数 +1 → `start_turn()` → `PLAYER`）。

## 敌人行动

- 敌人不出牌、不抽牌，只按状态机行动。
- 每个 `EnemyActionState` 是"本回合行动 + 后继状态"：`intent_text`、`effects`、`next_state`。
- 意图显示在精灵上方，玩家在出牌前可见；敌人死亡后隐藏。
- 状态机是线性的，没有随机或条件分支。
- 现有测试敌人 `character/templates/test_enemy.tscn` 是两状态循环：攻击 1 点 → 获得 1 点护甲 → 回到攻击。

设计内容见 `docs/敌人与Boss.md`。

## 战斗界面

- 拖牌到 `PlayZone` 或敌人身上出牌。
- 需要序列费用时，按顺序点选序列按钮：黄框为可选起点，青框为已选；`CancelPlay` 取消。
- `DrawButton` / `DiscardButton` / `ExhaustButton` 浏览三个牌堆，浏览顺序打乱。
- `RoundCount` 显示回合数，`cards_per_row` 控制手牌排布。
- 牌面由 `CardView`（`cards/scripts/card_view.gd`）渲染，监听 `CardData.changed` 以在编辑器内实时刷新。
